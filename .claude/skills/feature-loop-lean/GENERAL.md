# Lean loop (v45g)
Never call get_mcp_tools or any MCP tool: nothing you need is there, and each call replays your whole context.
Never: narration, subagents, MCP/get_mcp_tools, git/gh/dotnet, grep/glob/search/read tools (use Get-Context), docs/ (unless the issue names it), scripts/, terminal files, unrelated tests, merging. A call with no/empty output ("timed out") -> rerun the same command in the foreground (Submit reruns of an unchanged tree are cached); never run it in the background, never read terminal files. Script fails outside your code -> reply `SCRIPT_FAIL: <last line>`, stop (a `NEXT:` line is an instruction, never a failure). On GREEN, reply with the RESULT line Submit/WAIT_CMD prints last, then stop (no tool calls, todos, MCP, cleanup or handoff files).
1. `pwsh -NoProfile scripts/agent/Get-Context.ps1 -Issue N`: criteria, EXISTING files, a RECIPE (complete exemplar of this kind of change: copy its shape) and the likely edit target + sibling test (FULL = complete, never read; a long sibling test shows its last test + usings: append after it, don't read it). NEW names don't exist yet: never search for them; NEXT_SCRIPT = the DbUp file name to create. TEST SETUP/TESTS = helpers to reuse, tests already touching these symbols; ACCESS = whether UnitTests can see an internal target (if NOT, add the csproj line it prints). Need more? `Get-Context.ps1 -Find 'ExactType|regex'` (matching lines +2 context, capped) or `-File path` (big files show an outline; then `-File path:a-b`), never both; 2 extra calls, then 4 more as `-Find` or `-File` (plain, or batched ranges `-File 'a.cs:10-60,b.razor:1-40'`); after the NEXT line never call it again: edit. Never read via shell or grep/read tools, never touch /tmp/agent-*, never probe with edits. Never re-read. Unsure? Edit anyway: Submit and CI name what's missing. If EXISTING already meets every criterion, change nothing: `RESULT=ALREADY_DONE <file:line>`. Never add a duplicate type. Keep an endpoint's response format unless the criteria say otherwise.
2. Change only what the criteria need (vague asks: a change users can see, wired into a page/API, not just a helper), code + tests in few edits with the edit tool (never rewrite files via shell; keep their usings). New logic in a method with 4+ branches -> private helper.
Workflow/docs/build-script items: Get-Context prints the named files; Submit skips .NET checks.
3. `pwsh -NoProfile scripts/agent/Submit-Change.ps1 -Issue N -Branch B` (checks incl. affected acceptance tests, publish, waits; NO_CHANGES = you edited nothing yet). RISK/FIX:/*FAIL/CHECKS=RED -> fix exactly what it names (FIX: = local Qodana or acceptance test), rerun Submit. A FAIL that names nothing -> `SCRIPT_FAIL`, never dig. No GREEN/RED -> run WAIT_CMD until one. RED only in unrelated tests -> WAIT_CMD -ForceRerun once. PUBLISH_FAIL -> reply with it.
Traps: CRAP max CC 6; every new method needs a unit test; new query/command needs a validator + test. Qodana: no unused usings (implicit usings cover System, System.Linq, System.Collections.Generic, System.Threading.Tasks), no namespace-qualified type names (add a using), no `?.`/`??` on non-nullable, `[a, b]` not `new[] {}`, bUnit ClickAsync not Click, new option props copy the ReSharper AutoPropertyCanBeMadeGetOnly line, new Core/Model `{ get; set; }` props get `// ReSharper disable once PropertyCanBeMadeInitOnly.Global`; leave no unused members. New WorkOrder/query props must survive remoting: RemotableRequestTests fakes them via ObjectMother/BogusOverrides (a DateOnly prop needs a rule there like WorkOrder.DueDate). WorkOrder Number max 7. New max-length string columns get a ClampLength rule in BogusOverrides (CI SQL Server truncates). New anonymous API routes -> ApiPublicPathRules.PublicLeaves. A page that sends a new query on load needs it in every bUnit stub bus of that page (StubBus + each test's own). Tests: NUnit+Shouldly, ObjectMother; capturing ILogger<T> for logs.
