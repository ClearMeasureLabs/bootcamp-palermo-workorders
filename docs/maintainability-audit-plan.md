# Maintainability Audit & Remediation Plan — `bootcamp-palermo-workorders/src`

> Generated by the `inherited-code-audit` skill (SOLID, Onion/Clean Architecture,
> Fowler code smells, enterprise/domain patterns, Jeremy Miller guidance, AI-code
> anti-patterns, testing pyramid). Scope: the active `src\` tree only — the two
> `-fresh` snapshot copies were excluded. Every finding cites `file:line` and a
> named principle so the fix is defensible.

## Executive summary

This is a **high-quality, reference-grade codebase** built on Onion Architecture.
The layer graph is clean (framework-free `Core`, EF isolated in `DataAccess`,
Lamar IoC centralized, MediatR CQRS) and there is a genuine test pyramid
(~250 unit / 111 integration / 98 acceptance) that drives the real UI with
Playwright. The audit did **not** find systemic rot. It found a committed
secret, a recurring anemic-domain pattern on the aggregate, magic-string
duplication in the newer MCP/AI surface, and a testing gap where LLM calls are
skipped rather than stubbed (which conflicts with the project Definition of Done).

**Five systemic themes:**

1. 🔴 **Committed Azure secret** — rotate + remove.
2. 🟠 **Anemic `WorkOrder` aggregate** — the entity can't protect its own state;
   rules live in `StateCommand`s and `ChangeStatus(employee, date, status)`
   silently discards its arguments. *Highest-leverage design fix.*
3. 🟠 **Magic command-name strings** duplicated across the MCP tool's switch,
   `[Description]` attributes, and error text — the OCP hotspot, in the
   AI-generated surface.
4. 🟠 **LLM paths `Assert.Ignore`'d, not stubbed** — AI code (the biggest risk
   area) reports green with zero coverage in CI.
5. 🟡 **Newer AI/MCP/middleware code** carries the smells (duplication, empty
   validators, fat middleware); the older hand-crafted core is clean.

## Critical

### 🔴 Real Application Insights connection string committed to source & history
- **Principle:** Hardcoded secret
- **Location:** `src/ChurchBulletin.AppHost/appsettings.Development.json`,
  `src/Worker/appsettings.Development.json`,
  `src/Worker/Properties/launchSettings.json`,
  `src/UI/Server/Properties/launchSettings.json`, and `AGENTS.md` — key
  `586d68ed-…`, present across multiple commits.
- **Why it hurts:** Anyone with repo read access can forge telemetry / incur
  ingestion cost; the key is permanent in git history.
- **Fix:** Rotate the App Insights resource key now; replace literals with
  `APPLICATIONINSIGHTS_CONNECTION_STRING` via user-secrets/env/Key Vault; scrub
  history (git-filter-repo/BFG) since the repo is shared.
- **Severity note:** an AI ingestion key is lower blast radius than a
  DB/credential secret (telemetry forgery/cost, not data breach) — but it should
  not be in the repo.
- **Effort / Risk:** M.

## High

### 🟠 Anemic domain model — `WorkOrder` is a property bag; `ChangeStatus` ignores its args
- **Principle:** Anemic Domain Model (Fowler) — *flagged independently by two analyses*
- **Location:** `src/Core/Model/WorkOrder.cs:57-65`; rules in
  `src/Core/Model/StateCommands/*`; unused local at
  `src/Core/Model/StateCommands/StateCommandBase.cs:30`.
- **Evidence:** `ChangeStatus(Employee employee, DateTime date, WorkOrderStatus status){ Status = status; }`
  — `employee` and `date` are discarded. All invariants (valid transitions,
  who-may-act) live outside the entity; any caller can do `wo.Status = Complete`.
- **Why it hurts:** The entity cannot protect its own state; transition logic is
  scattered across the StateCommands folder; the signature promises audit
  behavior it does not deliver.
- **Fix:** Move guards/side-effects onto the aggregate (`wo.Assign(user, date)`);
  make `Status` a private setter mutated only through those methods; keep
  `StateCommand`s as thin orchestration. Either implement or delete the
  misleading overload and the dead local.
- **Effort / Risk:** M — state-command integration tests
  (`IntegrationTests/DataAccess/Handlers/StateCommandHandlerFor*Tests.cs`)
  protect the refactor.

### 🟠 MCP command dispatch = magic-string switch re-implementing existing polymorphism
- **Principle:** OCP + Magic strings + Shotgun Surgery — *flagged by three analyses*
- **Location:** `src/McpServer/Tools/WorkOrderTools.cs:86-140`.
- **Evidence:** Command-name literals (`"DraftToAssignedCommand"`, `"Shelve"`, …)
  duplicated across a `switch`, an `if` special-case, `[Description]` text, and
  the fallback error string — while `StateCommandList` +
  `StateCommandBase.Matches()` already resolve this polymorphically, and
  `InProgressToCompleteCommand` already has an unused `const string Name`.
- **Why it hurts:** Adding/renaming a command means editing many disconnected
  string sites that silently drift out of sync.
- **Fix:** Drive dispatch from `StateCommandList` keyed by a `Name` constant;
  build the error list by joining registry keys; move the "requires assignee"
  rule into the command's own validation.
- **Effort / Risk:** M — `McpWorkOrderToolTests.cs` covers it.

### 🟠 LLM/AI paths are skipped, not stubbed — violates the Definition of Done
- **Principle:** Testing — third-party interfaces must be stubbed/simulated
- **Location:** `src/IntegrationTests/LlmGateway/LlmTestBase.cs:11-21`,
  `src/AcceptanceTests/AcceptanceTestBase.cs:41-50`, plus ~10 files calling
  `Assert.Ignore` when no key / on HTTP 429.
- **Evidence:** No fake `IChatClient` exists; AI tests hit live Azure OpenAI or
  silently no-op. In keyless CI the LlmGateway, chat handlers, reformat agent,
  and MCP-LLM flows report green with zero signal.
- **Why it hurts:** The highest-risk (AI) code has no deterministic coverage;
  the suite is non-deterministic and costs money.
- **Fix:** Inject a fake `IChatClient` (`Microsoft.Extensions.AI` test clients)
  with canned responses wired via DI in the test host; keep one opt-in
  live-smoke category for real-key runs.
- **Effort / Risk:** M.

## Explicitly exemplary (no action — recorded so future audits don't re-flag)

- `Core` is genuinely framework-free (references only FluentValidation,
  MediatR.Contracts, `Microsoft.Extensions.*.Abstractions`).
- EF Fluent mapping isolated in `DataAccess/Mappings/*`; entities carry no ORM
  attributes — correct persistence ignorance. `EntityBase<T>` is a pure domain
  identity base, not an ORM base.
- `WorkOrderStatus` is a proper type-safe enumeration value object.
- Clock is abstracted via injected `TimeProvider` (`StateCommandHandler`).
- **No service-locator reach-through in business code**; DI is centralized in
  Lamar registries / `Program.cs`. Background-service `CreateScope()` use is the
  correct pattern.
- Genuine full-system test: `ServerFixture` boots the real UI.Server (+Worker)
  and Playwright drives login → create → assign → begin → complete.
- Every architectural seam (DB / HTTP / gRPC / WebSocket / MCP / messaging) has
  an integration test.

## Suggested backlog order

1. **Rotate + purge the App Insights key** (Critical — do first).
2. **Stub `IChatClient`** — unblocks trustworthy CI for all AI work (enables
   everything else).
3. **Enrich the `WorkOrder` aggregate** behind existing state-command tests
   (highest design leverage).
4. **Collapse the MCP magic-string dispatch** into the polymorphic registry.
5. **Medium cleanups:** header-name constant, remove `EmployeeSpecification.All`
   static, extract `ChatPanel`, re-tier the `WebApplicationFactory` tests.
6. **Low items** opportunistically.

Every High/Medium item has test coverage protecting the refactor except the
LLM-stub gap itself — which *is* the missing coverage. Per the project Definition
of Done, any behavior-changing remediation must ship with unit + integration +
full-system tests in the same change.

## Remediation progress log

Each phase below was gated by `./PrivateBuild.ps1` **and** `./AcceptanceTests.ps1`
locally before moving on. Baseline before any changes: PrivateBuild 261 unit +
111 integration green; AcceptanceTests 72 passed / 4 skipped.

### Phase 0 — Stabilize the acceptance suite (pre-req) ✅
The acceptance suite crashed nondeterministically at baseline. Root cause (via
crash-dump): the spawned `UI.Server` failed to bind port 7174 because a prior
run whose teardown was skipped (after a host crash) leaked the server —
a self-perpetuating cycle. Fixes:
- `ProcessCleanupHelper.EnsurePortFree` + call it before starting the server
  (`ServerFixture`) — frees the port up-front, breaking the cycle.
- `AcceptanceTestBase` navigation wait `NetworkIdle` → `DOMContentLoaded` (the
  app holds a persistent notification WebSocket, so the network never idles).
- `AcceptanceTests.runsettings` workers 8 → 4 (8 browsers overloaded the single
  shared server, causing navigation timeouts).
- Result: two consecutive green runs (72/4).

### Phase 1 — Remove committed secrets ✅
Emptied the App Insights key (`586d68ed…`) and a second OpenTelemetry key
(`62370908…`) from 6 tracked files (appsettings.Development.json ×2,
launchSettings ×4) and `AGENTS.md`. **Out-of-band (owner action required):**
rotate both Azure keys (already exposed in git history) and scrub history.

### Phase 2 — Stub the LLM (fake for text-only paths) ✅
- Extracted `IChatClientFactory` (DIP seam); 6 consumers now depend on it; DI
  wired in UI.Server (Lamar scan), UI.Client, Worker.
- Added deterministic `FakeChatClient`, gated by `AI_OpenAI_UseFake`. Integration
  `TestHost` enables it only when no real key resolves (env/appsettings/user-
  secrets), so keyless CI runs the text-only paths (translation, health-check)
  offline; a real key still exercises the live model.
- Agentic tool-calling tests tagged `LiveLlm` + `RequiresRealLlm`, skipped under
  the fake. 4 new unit tests cover the fake deterministically regardless of creds.

### Phase 3 — WorkOrder aggregate ✅
- Removed the misleading `ChangeStatus(Employee, DateTime, WorkOrderStatus)`
  overload that silently discarded its arguments, and the dead
  `currentUserFullName` local in `StateCommandBase.Execute`.
- Added entity behavior tests (`CanReassign`, `GetMessage`).
- **Deliberately deferred:** making `Status` a private setter. It is assigned via
  object initializers at ~79 sites (seed data, tests, factories); that is a
  high-blast-radius change best done as its own dedicated PR. Transition
  side-effects legitimately remain in the per-transition state commands (they are
  transition-specific, not status-specific — e.g. `Assigned` via DraftToAssigned
  stamps `AssignedDate` but via Shelve must not).

### Phase 4 — MCP command dispatch ✅
Replaced the command-name `switch` + special-case + hard-coded error list in
`WorkOrderTools.ExecuteWorkOrderCommand` with polymorphic resolution over
`StateCommandList.GetAllStateCommands`, matching by type name or transition verb.
Preserves the external command vocabulary (class names + `Shelve`).

### Phase 5 — Medium cleanups 🟡 partial
Done (gated green):
- `WorkOrderStatus.FromCode` now throws `ArgumentOutOfRangeException` on no match
  (mirrors `FromKey`) instead of returning null.
- API-key header single-sourced: `ApiRateLimitingOptions.ApiKeyHeaderName`
  defaults to `ApiKeyConstants.HeaderName`; removed the mismatched-case literal
  from `appsettings.json`.

**Remaining Phase 5 items (not yet done):**
- Remove the mutable static `EmployeeSpecification.All`; put `CanFulfill` on the
  `EmployeeGetAllQuery` request.
- Extract a shared `ChatPanel` component (dedupe `WorkOrderChat` /
  `ApplicationChat`).
- Re-tier the `WebApplicationFactory`-based tests out of `UnitTests` into
  `IntegrationTests`.
- Bind `DISABLE_AUTO_REFORMAT_AGENT` as a typed `IOptions<>` boolean.

### Phase 6 — Low items ⬜ not started
Empty validators, WO-number magic slice, duplicated `HealthStatus` mapping,
bulk-import handler extraction, demo-weather `DateTime.Now`→`TimeProvider`,
`[Retry]`/visibility-poll E2E hardening, trivial getter/setter test cleanup.

**Status:** working tree is green (PrivateBuild 267 unit + 111 integration;
AcceptanceTests 72/4) and every applied change has been gated. Changes are staged
in the working tree, not committed (on `master`; a feature branch + commit is the
next step when ready).
