# Python Django parity gaps

This prototype remains a staged rewrite. The matrix compares the checked-in Django models and migrations with the current EF Core mappings under `src/DataAccess/Mappings/`. It does not describe an earlier migration snapshot. Source references are `WorkOrderMap.cs`, `EmployeeMap.cs`, `RoleMap.cs`, `WorkOrderAttachmentMap.cs`, and `WorkOrderStatusConverter.cs`.

## Persistence schema matrix

| Area | Current .NET mapping | Django prototype | Gap / effect |
|---|---|---|---|
| Primary keys | UUID keys; Employee and Role IDs generated by the database, WorkOrderAttachment ID generated by the application | Auto-increment integer IDs for Employee, Role, WorkOrder; UUID for attachment | Key type and generation differ; external IDs and joins are not interchangeable. |
| Employee identity | UserName 100, FirstName 100, LastName 120, EmailAddress 255, PreferredLanguage 10 (`en-US` default); all required | username 100, first_name 100, last_name 100, email max 254 and optional; PreferredLanguage absent; `active` is an extra field | Last name and email limits differ; email nullability/default and language storage differ; active is prototype-only. |
| Role | Name 100; create/fulfill flags required | Name 50; flags required | Role name limit differs. |
| Employee roles | `EmployeeRoles` many-to-many table with composite EmployeeId/RoleId key | Django-generated many-to-many join table with integer FKs | Join table name and key types differ. |
| Work order number | Required string, max length 7 | Nullable during insertion, max length 30; generated as `WO-000001` | Format, length and nullability differ. Django numbers exceed the source column's max length. |
| Work order title | Required, max length 300 | Required, max length 200 | Django rejects some titles accepted by the source. |
| Description / instructions | Max length 4000; nullable in the EF mapping | Max length 4000; stored as non-null empty strings when blank | Null and empty-string behavior differs. |
| Room | Max length 900; nullable | Max length 900; stored as non-null empty string when blank | Null and empty-string behavior differs. |
| Status | Three-character codes `DRT`, `ASD`, `IPG`, `CMP`, `CNL` via `WorkOrderStatusConverter` | Descriptive values `Draft`, `Assigned`, `InProgress`, `Complete`, `Cancelled` (field max 20) | Database representation and column width differ; status data needs conversion. User-facing labels are intentionally friendly. |
| Creator / assignee | Creator FK required by the current schema; Assignee FK nullable; delete restricted | Both FKs nullable; `SET_NULL` on employee deletion | Creator nullability and deletion behavior differ. |
| Work order dates | CreatedDate, AssignedDate, CompletedDate nullable datetimes; DueDate SQL `date` | created_at non-null datetime default; assigned_at/completed_at nullable datetimes; due_date nullable date | Created-date nullability/default differ; due-date storage matches date-only semantics. |
| Status history | Current final SQL schema has no WorkOrderEvent table; legacy AuditEntry was removed in migration 020 | `WorkOrderEvent` table stores transitions and notes | Django adds a persistence table beyond the current source schema. |
| Attachment metadata | UUID ID; required WorkOrderId, FileName 500, ContentType 200, FileSize bigint, UploadedById, UploadedDate; work-order delete cascades and uploader delete restricts | Same field lengths and bigint size; UUID generated in Django; same cascade/restrict intent | Column shape is close; UUID generation and integer FK types differ. Django stores metadata only, no file bytes. |
| Database schemas | Core entities map to `dbo`; migration 022 creates the `[nServiceBus]` schema for transport | Django tables use the app's default database schema | Schema names and transport setup are not reproduced. Migration 022 creates a schema, not core tables. |

## Visible UI gaps

The Django shell now has the source's 280px left rail, white top header, centered search heading, result-card treatment, and styled work-order detail card. The current rail omits Counter, Fetch Data, AI Agent, and Settings routes because the Django prototype does not implement those pages. Its footer also does not reproduce the source health/version link. Work-order detail shows read-only fields and status commands; it does not yet reproduce the source's editable title/description/room fields, speech controls, chat panel, or every permission-dependent command state.

The headful acceptance workflow captures the search and detail views at 1365×900. These screenshots document the current prototype UI; they do not establish full visual or behavioral parity.
